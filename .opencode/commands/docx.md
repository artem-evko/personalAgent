Собери готовый `.docx` из текущего черновика работы командой pandoc. Выполни по шагам:

1. Найди исходный Markdown-файл работы (обычно `text.md` в корне проекта или путь, который укажет пользователь) и файл библиографии `refs.bib` рядом с ним. Если их нет — спроси пользователя пути.
2. Проверь, что в тексте каждая ссылка на источник оформлена как `[@ключ]` или `[@ключ, с. N]` (цитирование pandoc), а не как ручной `[10, с. 81]` — вручную проставленные номера pandoc не пересчитает.
3. Шаблоны оформления (`gost.docx`, `gost-numeric.csl`) лежат в `~/.config/opencode/templates/` (ставятся один раз через `setup.ts`, общие для всех проектов). Если их там нет — возьми из `templates/` этого репозитория. Выполни команду (замени пути на реальные, PowerShell, кавычки обязательны при пробелах в пути):
   ```
   pandoc "text.md" --reference-doc="$HOME/.config/opencode/templates/gost.docx" --citeproc --bibliography="refs.bib" --csl="$HOME/.config/opencode/templates/gost-numeric.csl" -o "out.docx"
   ```
   Если `pandoc` не в PATH, вызови его полным путём `~/.local/bin/pandoc.exe` (на Windows — `$HOME\.local\bin\pandoc.exe`).
4. После сборки открой результат и сверь по методичке: разрыв страниц перед разделами (Heading 1), стиль подписей таблиц/рисунков, список источников в конце с нумерацией по первому упоминанию.
5. Напомни пользователю, что pandoc НЕ делает сам:
   - титульный лист (вставляется вручную по форме вуза или отдельным шаблоном);
   - номер формулы у правого края страницы;
   - буквенную нумерацию объектов в приложениях (`Рисунок А.3`);
   - реферат и содержание — содержание можно сгенерировать (`--toc`), реферат пишется отдельно.
6. Отчитайся кратко: что собрано, что нужно доделать руками в Word.
